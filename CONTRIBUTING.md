# Contributing

Thank you for helping build Return to the Void. The project is in pre-production, so contributions should improve a verifiable milestone rather than broaden the concept.

## Before opening work

1. Read [README.md](README.md), [ROADMAP.md](ROADMAP.md), and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
2. Search existing issues and pull requests.
3. For substantial changes, open an issue describing the problem, proposed scope, and acceptance criteria.
4. Do not add Epic Games assets, extracted game content, secrets, or material you do not have permission to redistribute.

## Pull requests

Keep each pull request focused. Include:

- the problem being solved;
- the behavior before and after;
- validation performed;
- screenshots for visual changes;
- documentation updates when responsibilities or interfaces change.

Run:

```bash
python3 scripts/validate_repo.py
```

A contribution is ready when its stated acceptance criteria pass, links and documentation remain accurate, and no unsupported “implemented” claims are introduced.

## Licensing

By contributing documentation or website content, you agree to license that contribution under CC BY 4.0. Source code is not yet accepted under a general code license; open an issue before contributing substantive code so maintainers can establish an appropriate code license.
