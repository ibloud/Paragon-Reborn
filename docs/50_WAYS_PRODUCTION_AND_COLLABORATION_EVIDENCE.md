## Purpose

This addendum records the user's account of the intended production workflow and the distinction between engineering services, production authorship, and exploratory discussions with prospective collaborators.

This is an evidence-organizing document, not a legal conclusion. Statements attributed to the user should be corroborated against contracts, invoices, session metadata, email, messages, and the underlying audio/session files where available.

## 4. Provenance distinction to preserve

For the 50 Ways evidence model, keep these roles separate:

**Composition / lyrics**
→ User's human-authored work

**Original recording / source session**
→ Recording and mixing engagement; identify engineer/studio and session custody

**Engineering**
→ Vocal/drum timing, recording, editing, mixing, and other documented engineering work within the agreed scope

**Production**
→ Separate role; do not attribute production authorship merely because an engineer created a mix

**Prospective collaborators**
→ Conversations and demonstrations do not become engagements unless the evidence establishes acceptance/scope

**Later realization layers**
→ Suno realization, MIDI/transcription, Synthesia implementation, and web presentation should each have their own provenance records

## Evidence labels

Use these labels consistently throughout the project:

- **FACT** — directly observable in a preserved artifact.
- **DOCUMENTED** — stated in a dated correspondence or other record.
- **CORROBORATED** — independently supported by two or more evidence sources.
- **USER-REPORTED** — user's recollection or account awaiting corroboration.
- **REQUIRES RIGHTS REVIEW** — legal status should be verified rather than assumed.
- **NOT ESTABLISHED** — the present evidence does not establish the proposition.
